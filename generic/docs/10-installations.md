# 10 · Installations: generic (in the cluster) and Azure

**The Loki backend is the same in both installations:**
- OTel agents;
- Kafka;
- OTel gateways;
- distributed, zone-aware Loki, with index gateways and a ruler (recording rules);
- the recorded-metrics store and its tenant guard;
- memcached;
- the read gateway;
- Grafana with an org per tenant;
- the NetworkPolicies.

Only the services *around* it change: storage, secrets, the database, sign-in and
monitoring. That is what the platform team validates once, and installs in either
profile ([ADR 0011](adr/0011-two-installation-profiles.md)).

## Generic: everything in the cluster

![Generic installation](../diagrams/08-generic-in-cluster.png)

`environments/generic/` · manifests: [`manifests/generic/`](../manifests/generic/README.md)

| Part | Runs as | Provided by |
|---|---|---|
| Kafka | Strimzi cluster `logs` in ns `kafka` | operators chart (Strimzi) + platform chart (cluster, topic, users) |
| Sign-in | Keycloak in ns `keycloak`, realm `obs` | operators chart (Keycloak operator) + platform chart (`keycloak.install`) |
| Grafana's and Keycloak's database | PostgreSQL by the **Percona operator**, ns `postgres` | **you**: [`examples/percona-postgresql.yaml`](../examples/percona-postgresql.yaml); the chart copies the user Secrets |
| Secrets | Kubernetes Secrets generated by the chart, kept across upgrades | platform chart (`keyVault.enabled: false`) |
| Monitoring, alerts | PodMonitors + PrometheusRule | platform chart; **your** Prometheus Operator (e.g. kube-prometheus-stack) |
| Load balancer | kgateway Gateway, internal | platform chart; `grafanaAccess.loadBalancerAnnotations` for your LB |
| Log storage | Azure Blob **for now**; any S3 API with `overlays/s3-storage.yaml` | Terraform's storage account + Loki identity, or your S3 store |

Before `scripts/install.sh generic`:
1. **PostgreSQL**: install the Percona operator and the cluster in namespace `postgres`. It
   creates the Secrets `obs-pg-pguser-grafana` and `obs-pg-pguser-keycloak`:
   ```bash
   helm repo add percona https://percona.github.io/percona-helm-charts/
   helm install pg-operator percona/pg-operator -n postgres --create-namespace
   kubectl apply -f examples/percona-postgresql.yaml
   ```
   Step 25 of `install.sh` checks for them; step 30 copies them to `grafana/grafana-db` and
   `keycloak/keycloak-db`. If you change a password in PostgreSQL, run step 30 again.
2. **Prometheus Operator**: its CRDs must exist (`monitoring.coreos.com`). Set
   `monitoring.prometheusOperator.labels` to what your Prometheus selects on, or turn it off.
3. **DNS** for `grafanaAccess.hostname` and `keycloak.hostname`, both pointing at the
   Grafana load balancer.
4. **Certificates**: `selfSigned: true` gives a working lab (browsers warn). For real use, set
   `selfSigned: false` and create `grafana/grafana-tls` and `grafana/keycloak-tls`, for
   example with cert-manager.
5. **Log storage**:
   - Blob: the storage account and Loki's managed identity from Terraform, as for Azure;
   - or S3: list `s3-storage.yaml` in `overlays.txt` and create `loki/loki-s3`
     (see the overlay's header).

After the install:
- Keycloak's temporary admin is in Secret `keycloak/keycloak-initial-admin`. Sign in at
  `https://<keycloak.hostname>/admin/`, create a permanent admin, then delete `temp-admin`.
- The lab users (`alice`, `bob`, `carol`, `platform`) sign in to Grafana through Keycloak
  with `change-me-now`, and must choose a new password.
- Grafana's local `admin` still exists, with initial password `change-me-now`
  ([06](06-operations-runbook.md#the-local-admins-password)).

To sign in with the bank's Entra ID through Keycloak, set `keycloak.realm.entraBroker`
(`tenantId`, `clientId`) and create Secret `keycloak/keycloak-entra` (key `client-secret`).
The realm maps Entra group object IDs (`tenants.yaml` `groups.entra`) to its groups
(`groups.oidc`).

## Azure: Azure services around the same backend

![Azure installation](../diagrams/09-azure-components.png)

`environments/azure/` · manifests: [`manifests/azure/`](../manifests/azure/README.md)

| Part | Azure service | Provided by |
|---|---|---|
| Log storage | Blob GZRS, private endpoint, Workload Identity, CMK | Terraform |
| Secrets | Key Vault (premium, HSM) + External Secrets | Terraform + operators chart (ESO) |
| Grafana's database | Azure Database for PostgreSQL flexible server (zone-redundant HA) | Terraform |
| Sign-in | Entra ID directly (or Keycloak / OIDC) | the bank's IAM (app registration, groups) |
| Monitoring, alerts | Azure Monitor managed Prometheus; rule groups from the same alert file | AKS add-on + Terraform |
| Disks, nodes | disk encryption set (CMK); zonal node pools `loki1/2/3` | Terraform |
| Kafka | **in the cluster**, as in generic (Strimzi) | the charts |

The first install is [06 · First install](06-operations-runbook.md#first-install).

## What changes, side by side

| | Generic | Azure |
|---|---|---|
| `keyVault.enabled` | `false` | `true` |
| `postgres.provider` | `percona` | `azure` |
| `keycloak.install`, `auth.provider` | `true`, `keycloak` | `false`, `entra` |
| `monitoring` | `prometheusOperator.enabled: true` | `azurePodMonitors: true` |
| Loki storage | Blob for now; `s3-storage.yaml` | Blob |
| Secret rotation | delete the Secret, re-run step 30 (view keys: also step 40) | `scripts/tenant-keys.sh --rotate`; Key Vault versions |
| Encryption at rest | the cluster's disks and the object store's | CMK in Key Vault for Blob and disks |
| Audit of secret access | Kubernetes audit log | Key Vault diagnostic logs |
| You also run | Keycloak, PostgreSQL (Percona), Prometheus | — (Azure runs them) |

Both installations pass the same checks (`scripts/validate.sh`, `scripts/pipeline-test.sh`).
